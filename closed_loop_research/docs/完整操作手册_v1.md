## 1. 系统做什么，以及几个基本概念

系统用历史数据研究多个因子的组合，将研究结果固定成一个模型，再由模型给股票打分。你可以在这些分数基础上加筛选条件，得到排名靠前的股票名单。

```text
导入数据并核验时点
        ↓
建立研究实验，固定数据、参数和预算
        ↓
生成候选因子 → 搜索组合 → 回测评价 → 奖励反馈 → PPO更新
        ↑                                      ↓
        └────────── 下一批研究 ────────────────┘
        ↓ 注册预算结束
V段选择模型 → 冻结模型 → 独立T段测试
        ↓ 查看证据并设为可用
模型给完整范围打分 → 用户过滤 → 取Top N
        ↓
查看解释、保存方案、查看历史、导出名单
```

T测试有独立入口。单个实验训练结束会自动完成V选择并登记候选，不会自动启动T测试或自动开放前台。模型管理将使用状态、评价状态和数据就绪分别记录；“评价完成”不等于T已经运行，应查看T一栏。

### 1.1 日常用语

| 名称 | 用普通话理解 | 例子 |
|---|---|---|
| 因子 | 给股票计算一个特征值的公式 | 过去20个交易日收益率 |
| 因子池 | 当前研究保留的一组公式 | 动量、短期反转、低波动 |
| 初始化因子池 | 给研究一个可比较的起点 | 先放入3个已定义公式，再尝试改进 |
| 组合 | 使用哪些因子，以及各自占多大权重 | 40%、30%、30% |
| PPO | 根据候选的反馈，更新以后生成公式的策略 | 学习哪些公式更值得尝试；不直接下买卖单 |
| 数据快照 | 固定版本的数据与质量记录 | 同一次实验始终使用同一个快照 |
| 项目 | 一组相关研究的组织容器 | 价量组合增量研究 |
| 实验 | 一次固定协议、数据和随机种子的运行 | 种子7、2批、每批4候选 |
| 模型版本 | 冻结的公式、权重和计算规则 | 改名不会改变这个版本的公式 |
| 方案 | 具体模型版本＋条件＋数量 | 原型一号，上市满365天，Top 20 |
| 结果 | 在某个实际数据日算出的名单 | 2026-06-16的50只股票及贡献 |
| Top K | 研究回测中的固定目标股票数 | 当前模板为50 |
| Top N | 本次选股希望输出的股票数 | 可以输入10、20或50 |

**方案保存的是“以后怎么算”，结果保存的是“这次算出了什么”。** 保存方案不会开始计算；成功计算会自动保存结果。

### 1.2 F、E、V、T分别是什么

它们是按时间划分的四段数据，不是四类因子。

| 分区 | 工作 | 不做什么 | 当前模板日期 |
|---|---|---|---|
| F：拟合段 | 搜索因子子集、调整组合权重 | 不使用后面的数据拟合 | 2021-12-15—2023-09-21 |
| E：反馈段 | 比较新组合与基线，计算奖励 | 不把T结果拿来奖励PPO | 2023-09-22—2024-12-10 |
| V：选择段 | 从预登记检查点中选出模型 | 不充当每个候选的训练奖励 | 2024-12-11—2025-08-26 |
| T：测试段 | 模型冻结后做最终历史测试 | 不反馈训练、调参或重新选优 | 2025-08-27—2026-06-16 |

前面的数据还用于指标预热。新快照的默认日期根据实际交易日历生成，应以实验中显示的协议为准。当前T历史已被观察，因此显示为历史测试，不能当作全新未观察数据。

### 1.3 当前已经准备好的内容

- 数据：固定500股，601,000行，1,202个交易日，2021-06-18至2026-06-16。
- 导入50个所需源字段；保留完整441字段目录；研究模板开放24个价量信号字段。
- 可用模型：**500股价量组合 · 原型一号**。
- 当前模型公式：20日动量40%、5日反转30%、低波动30%。来自E组种子7的完整研究，已完成V选择和历史T测试。
- 已生成一份默认Top 50名单，可以直接到“选股记录”查看。
- 其他8个版本仍是候选。当前各版本最终因子和权重相同，所以只开放一个代表版本。

这些是编写时的实际状态，不是固定业务限制。后续导入、实验和开放会产生新记录。

## 2. 五分钟完成第一次选股

### 2.1 直接查看已经生成的名单

1. 打开系统。
2. 左上工作区下拉框选择“选股工作区”。
3. 点击左侧“选股记录”。
4. 找到“500股价量组合 · 原型一号”、实际数据日为2026-06-16的记录。
5. 点击“查看结果”。向下查看名单，点击股票名称或“查看解释”查看贡献。
6. 如需保存到本地，点击“导出完整名单”。

### 2.2 自己生成一份名单

1. 点击“选股工作台”。
2. 在“选股模型”中选择“500股价量组合 · 原型一号”。
3. 核对右侧实际数据日期。现在显示2026-06-16，计算使用这一天的历史数据。
4. 第一次使用可以清空附加条件，将Top N设为50。
5. 点击“生成选股结果”。看到排队/运行状态后等待完成，不必重复点击。
6. 成功后下方显示名单，同时自动保存到“选股记录”。

想体验筛选，可以设置“上市天数最低值”为365、Top N为20，再生成一次。上市天数使用自然日，不是交易日。新结果单独保存，不会覆盖前一次。

**当前换手率、日成交额、板块、行业、市值及财务过滤没有开放。灰色输入框表示不可用，不要尝试把未知数值当作0来筛选。**

## 3. 启动、关闭与重新打开

### 3.1 服务已经运行时

直接打开 [系统入口](http://127.0.0.1:8767)。浏览器页面关闭不会关闭后台Python服务。浏览器刷新不会重新训练模型。

### 3.2 服务没有运行时

打开PowerShell，执行：

```powershell
Set-Location -LiteralPath 'F:\my_code_file\因子构建\生成因子＋回测系统'
python -m closed_loop_research.app --port 8767
```

保持该终端运行，然后打开系统入口。另一种方式是在项目根目录执行：

```powershell
.\closed_loop_research\scripts\start_system_v1.ps1
```

只有环境缺少依赖或换了电脑时，才需要先执行：

```powershell
python -m pip install -r closed_loop_research/requirements.txt
```

当前实现已在Python 3.11环境验收。页面使用静态JavaScript和CSS，不需要先运行npm或单独启动前端服务。

### 3.3 正常关闭

1. 查看“任务状态”。
2. 普通研究若要稍后继续，先在实验“运行与迭代”页点击“检查点暂停”，等状态变为已暂停。
3. 导入、多种子对照和最终测试目前没有页面暂停按钮，正常关闭前等待其结束。
4. 回到运行服务的终端，按Ctrl+C，等待进程退出。

如果直接强行结束进程，下一次启动会把未完成任务标为中断。研究需显式恢复，选股需重新提交；不会自动续跑所有任务。

### 3.4 启动注意事项

- 8767是新系统；8766是旧报告服务，两者不是同一个入口。
- 同一个数据目录只能运行一个服务。已启动时不要反复执行启动命令。
- 服务只监听本机，手机或其他电脑不能直接使用这个127.0.0.1地址。
- 改端口可使用 `--port 8769`，同时改变浏览器地址；这不能绕过同一目录的单实例限制。
- 不要为了“重置页面”删除实验、模型或数据文件。页面刷新和服务重启通常足够。

## 5. 数据中心：检查、导入和更新

### 5.1 查看现有数据

进入“研究工作区 → 数据中心”，查看证券数、交易日、数据行数、最新完整实际日和覆盖区间。点击“字段与质量”，依次查看：

1. “质量报告 / 时点与来源”：原始来源、时点风险、质量结果。
2. “可用过滤与禁用原因”：哪些条件能使用、不能使用的具体原因。
3. “快照与证券范围”：实际日期和固定股票范围。
4. 字段目录：直接展示字段名、中文说明、文档备注、用途与可用性、说明来源和详细元数据；搜索框支持字段名、中文说明和备注。

中文说明按用户提供的《日K表字段说明.md》逐字段匹配。当前441字段中425个匹配，另外16个证券基础字段未被该文档收录，会明确标记；展开“说明文档未收录的字段”可查看清单。“来源与元数据”保留文档行号、章节和指纹。原文说明不等于实际值、单位或历史时点已经通过核验。

字段出现在目录中，并不表示可以用于训练。导入、隔离存储、训练白名单、前台过滤是不同权限。

### 5.2 从页面导入或更新

已有快照可以直接使用，不用每次打开系统都导入。源文件有新内容或需要首次建立快照时：

1. 确保原始文件和500股名单文件已在登记位置。
2. 点击“导入 / 更新数据”。
3. 系统跳转“任务状态”，展开对应任务查看进度。
4. 等任务成功，再返回数据中心点击“刷新”。
5. 检查新快照覆盖时间、质量和过滤状态。成功导入不等于所有字段核验通过。

页面读取固定登记文件，不提供任意CSV上传：

```text
原始行情及主数据：
F:\my_code_file\因子构建\数据\daily_with_maindata_v2.csv

固定500股代码名单来源：
F:\my_code_file\因子构建\生成因子＋回测系统\single_factor\data\selected_500_liquid_processed\panel.parquet
```

原始文件约19.8GB、制表符分隔。程序顺序扫描源文件，只保留指定500股及所需列，不把全市场全部列载入内存。本机已完成的成功导入约5.5分钟，实际耗时取决于硬盘、内存和队列；这不是运行时限承诺。

重复输入不会覆盖旧快照。导入不会自动重训模型，也不会自动更新已有历史结果。

### 5.3 更新后哪些对象会改变

| 对象 | 数据更新后的行为 |
|---|---|
| 已存在实验 | 继续绑定原数据和原协议 |
| 已冻结模型 | 公式、权重和范围不变；检查新数据是否兼容 |
| 已保存方案 | 保留模型版本、条件、N；重新运行时使用兼容的最新可用快照 |
| 已保存结果 | 保留当时的数据、日期、条件和名单 |

模型要求股票范围、计算规则、字段和历史覆盖兼容。不能仅因为文件更新了，就强行让旧模型跨范围使用。导入后刷新工作台或重新加载方案，核对页面日期再提交，避免沿用旧页面已选的快照。

### 5.4 当前字段限制

| 条件/数据 | 当前状态 | 原因或规则 |
|---|---|---|
| 上市天数 | 可筛选 | 实际数据日减上市日的自然日差；包含边界 |
| 换手率 | 禁用 | 最新5个交易日全部为0但存在成交，疑似占位 |
| 日成交额过滤 | 禁用 | 绝对金额单位尚未充分核验 |
| 上市板块 | 禁用 | 板块字典及历史变更未核验 |
| 行业、市值 | 未开放 | 缺少已核验接入与口径 |
| 财务训练及过滤 | 禁用 | 披露日期与历史修订存在时点风险 |
| 价量原型研究 | 可运行 | 仍保留样本偏差、复权/公司行动、成交近似限制 |

价量模板中的 `amount` 是原型研究字段；这不代表已经确认其绝对货币单位可用于用户的金额阈值过滤。当前可用三因子模型不依赖amount字段。

## 6. 研究项目：建立实验与配置协议

### 6.1 新建项目

1. 进入“研究工作区 → 研究项目”。
2. 点击“新建项目”。
3. 填写项目名称，例如“500股价量组合研究”。
4. 在“研究问题”中写清楚想检验什么，例如“加入交易增量反馈，能否比随机候选获得更好的组合”。
5. 点击“创建项目”。

项目用于整理实验，不会立即训练。名称建议控制在120字以内。点击项目卡片的“查看实验 →”可聚焦项目。

### 6.2 新建实验

1. 点击“新建实验”。
2. 填实验名称、所属项目、数据快照。
3. 查看自动生成的参数面板；完整协议 JSON 位于折叠的高级编辑区，通常无须打开。
4. 第一次运行保持默认的小预算，确认日期、费用、初始组合、奖励模式和生成器。
5. 点击“创建实验草稿”。
6. 在“实验配置”页复核；此时尚未运行。

**参数提交以完整协议JSON为准。** 修改参数面板会同步更新JSON；直接编辑JSON后可点“从 JSON 更新参数面板”。切换数据快照会重新生成模板，先选数据，再调整参数。

已创建实验没有原地编辑协议的保存按钮。要修改设置，点击“派生新实验”，编辑后创建新对象。派生复制协议和数据选择，不等于从原实验的PPO权重继续训练；继续原运行应使用“恢复”。

### 6.3 常用参数

下面是当前快照的原型模板，不是通过研究证明的最优参数。

| 参数 | 默认值 | 含义与操作提醒 |
|---|---:|---|
| 随机种子 `seed` | 7 | 固定随机过程；对照不能只挑最好种子 |
| 研究Top K `top_k` | 50 | 回测目标股票数；不同于页面临时Top N |
| 批次数 `batches` | 2 | 外层迭代次数 |
| 每批候选 `episodes_per_batch` | 4 | 每批生成的候选数 |
| 组合搜索预算 `search_budget` | 6 | 每侧组合搜索预算；不是总候选数 |
| 最大回测次数 `max_backtests` | 1000 | 总体资源约束，影响能否完成注册预算 |
| 风险 λ `risk_lambda` | 1 | 目标中对日对数收益波动的惩罚系数 |
| 复杂度 β `beta` | 0.01 | 惩罚组合公式复杂度增加 |
| 奖励尺度 τ `tau` | 0.1 | 增量映射到奖励的尺度，必须大于0 |
| 接受阈值 δ `delta` | 0.00000001 | 池更新须超过的改善门槛 |
| 生成器 `generator` | ppo | PPO、随机或固定因子 |
| 奖励目标 `reward_mode` | trade_delta | 默认使用配对交易增量 |

增加批次数时也检查JSON中的 `selection_batches`。例如注册4批、只在第2和第4批选模型，应将其设为 `[2, 4]`。检查点必须为升序、不重复且在批次数范围内。

日期必须按F、E、V、T先后排列且不重叠，落在实际数据范围内，并保留足够历史预热。界面允许编辑日期，不代表服务会接受任意日期或无效分区。

### 6.4 费用与成交参数

| 参数 | 当前默认值 | 说明 |
|---|---:|---|
| `initial_cash` | 1,000,000 | 初始模拟资金 |
| `lot_size` | 100 | 买入手数约束 |
| `buy_fee` | 0.0003 | 买入费率，即0.03% |
| `sell_fee` | 0.0013 | 卖出费率，即0.13% |
| `minimum_fee` | 5 | 最低费用参数 |
| `slippage` | 0.0005 | 滑点比例，即0.05% |
| `annual_days` | 252 | 年化换算参数 |

它们是本实验假设，不表示已经验证为每一年、每家券商的真实费用。费率输入小数比例，例如0.0003，而不是0.03。研究采用收盘信号和后续交易时点；不会把当日收盘信息用于此前成交。

### 6.5 奖励与结果如何理解

默认交易目标使用净收益序列的日对数收益，计算年化平均值并扣除波动惩罚。`objective`不是简单累计收益，也不是胜率。

默认交易增量奖励的思路是：

```text
原始增量 = 新组合的E段目标 − 基线组合的E段目标
           − β ×（新组合复杂度 − 基线复杂度）

若新候选没有被最终组合采用，有效增量记为0。
奖励 = tanh（有效增量 / τ）。
```

重复因子奖励为0；质量失败按明确规则记为−1；合法负增量保留为负奖励。文件、数据或计算基础设施故障会报错，不伪装成普通坏因子。

页面还提供单因子IC、组合IC和绝对交易表现等奖励选项。它们用于方法对照，不能与交易增量数值混作同一个指标；第一版正式机制对照入口固定覆盖A/B/C/E四组。

## 7. 研究运行：启动、暂停、恢复和停止

### 7.1 启动

打开实验的“运行与迭代”页签，点击“启动实验”。系统排队、准备独立研究快照，然后逐批运行。协议、数据和随机状态受到一致性校验。

可以查看候选数量、PPO更新、因子池版本记录和批次进度。因子池“记录数”包含初始记录，不等于发生了同样次数的有效改进，应查看池提交内容。

每批包括：冻结基线与策略、生成候选、质量检查、F段组合搜索、E段反馈、PPO更新、最多一次池提交与检查点保存。运行完成后自动进入V选择，登记候选模型。

### 7.2 四个按钮的区别

| 按钮 | 什么时候使用 | 结果 |
|---|---|---|
| 启动实验 | 草稿首次运行 | 进入队列并开始计算 |
| 检查点暂停 | 暂时让出计算资源，之后还要继续 | 在完整批次检查点暂停，保留续跑状态 |
| 恢复 | 已暂停、中断或已排除原因的失败实验 | 使用原协议、快照和检查点继续 |
| 停止 | 本次实验不再继续 | 终结本次运行，保留已有证据；没有“恢复已停止”入口 |

暂停/停止不是即时杀进程。请求后可能要等当前快照准备或批次完成；页面显示请求中时不要重复点或强行删除文件。进入模型选择阶段后，部分控制按钮不可用。

完成实验若要增加预算，使用“派生新实验”。不能修改原协议后按恢复，也不能把停止实验假装成完整注册实验。

### 7.3 看懂状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| 草稿 | 已保存，未启动 | 核对协议后启动 |
| 排队 | 等待计算队列 | 在任务状态查看前面的工作 |
| 准备/运行中 | 正在准备数据或计算 | 等待或申请检查点暂停 |
| 暂停请求/停止请求 | 已收请求，尚未到安全边界 | 等状态变化 |
| 已暂停 | 已保存可恢复状态 | 点击恢复 |
| 已停止 | 本次运行终结 | 需继续研究时派生新实验 |
| 中断 | 服务退出等导致任务未完成 | 重启后检查记录，再恢复 |
| 失败 | 有具体错误 | 先看错误、处理原因，再恢复或新建 |
| 选择中 | 正在做V选择和登记 | 等待完成 |
| 已完成 | 训练及V模型交接完成 | 查看模型；T是否完成另查验证报告 |

这套暂停/恢复按钮用于普通研究实验。数据导入、多种子对照、选股和最终测试任务没有同等控制能力，不能把普通研究的恢复规则套给所有任务。

## 8. 查看因子、组合和回测

### 8.1 运行与迭代

“候选评价轨迹”显示表达式、状态、奖励、增量和错误，展开“记录”查看完整证据。“PPO参数更新”显示更新记录、参数变化和训练信息。

候选数量增加、PPO参数发生变化，仅证明进行了搜索和学习，不等于收益改善。看到负奖励、重复因子、质量失败或池未变化，都可能是正常研究结果。

### 8.2 因子与组合

查看每个池版本的因子和权重；下方“V分区模型选择”展示选择证据。存在冻结模型后可点击“查看冻结模型”。

初始化池是起点，后面是否替换由真实评价和门槛决定。本次已有模型最终仍保留初始三因子，不代表PPO没有运行，而是本次搜索没有找到满足规则的更优提交。

### 8.3 回测与选股

1. 切换到“回测与选股”。
2. 如列表尚未更新，点击“载入已运行回测”。
3. 在“我想查看”中选择研究用途，再从“具体结果”选择带有轮次和用途名称的回测。默认优先打开已运行的冻结测试结果。
4. 查看总收益、最大回撤、年化波动、费用合计和实际资产净值曲线。
5. 展开“评价指标、冻结权重与协议标识”查看详细口径。
6. 在“查看回测交易日”中选择日期。
7. 查看信号日期、现金、持仓市值、费用，以及目标名单和实际持仓差异。
8. 展开当日订单、模拟成交、公司行动记录，解释未成交或部分成交原因。

**目标入选不等于实际持有。** 资金、手数和成交约束可能使两者不同；没有被新名单选中也可能仍有未能卖出的持仓。研究回测中的当日名单与前台在最新日计算的名单用途不同。

这里只读取已完成产物，不会因为选择页面选项就重新执行回测。未运行的T不会出现在列表；不存在的数据不显示为0收益。

### 8.4 指标解释

| 指标 | 应如何读 |
|---|---|
| 总收益 | 指定分区的累计净值变化；不是全年必然收益 |
| 年化收益 | 按协议年化天数折算；不是未来预测 |
| 最大回撤 | 期间从高点回落的最大幅度；当前显示可为负数 |
| 年化波动 | 收益波动的年化统计量 |
| 费用合计/滑点 | 模拟交易按照协议产生的成本 |
| 目标值 objective | 本研究优化的收益与风险综合目标 |
| 正/负奖励 | 候选相对评价反馈，不是单笔交易盈亏 |

## 9. 模型验证与多种子对照

### 9.1 单个模型的T测试

1. 等实验完成并已有冻结模型。
2. 进入“验证报告”。
3. 确认F/E/V/T区间和数据限制。
4. 点击“运行冻结模型 T 测试”。
5. 在任务状态或当前页等待结果，查看“最终测试 / T 实际报告”。

T是在公式和权重固定后才运行的。已有T结果不应当用来反复选参数；当前数据也不能重新标注为未观察。按钮已禁用时，先检查是否尚未冻结，或T已经完成。

### 9.2 新运行一套A/B/C/E对照

这会启动新的实际计算，与仅查看已有实验的比较不同。

1. 打开想用作基础的实验，确认它的完整协议。
2. 进入“验证报告”，点击“启动多种子对照”。
3. 填写逗号分隔的不同整数种子，例如 `7, 19`；服务要求2至10个不同种子。
4. 按本次预定研究计划决定是否勾选“全部组冻结后执行最终 T 测试”。
5. 点击“启动对照任务”。
6. 到“任务状态”查看任务；完成后返回项目刷新，查看“多种子机制对照”和各成员实验。

| 组别 | 方法 | 主要用途 |
|---|---|---|
| A | 固定因子基准 | 看复杂方法是否优于基础组合 |
| B | 随机生成候选＋交易增量评价 | 区分PPO学习与随机搜索效果 |
| C | PPO＋单因子IC奖励 | 比较单因子信号反馈与组合交易反馈 |
| E | PPO＋交易增量奖励 | 本系统主要研究方向 |

对照使用当前实验协议派生运行。所有组训练完成后统一V选择，全部冻结后才执行可选T。不要运行中修改文件或单独挑一个最好种子代替全部结果。

当前页面不提供失败对照任务的一键检查点恢复。出现失败时保留原任务、查看原因，修复后另建对照；不要删除失败证据后假装是首次运行。

### 9.3 比较已有实验

在“研究项目”列表勾选至少两个实验，点击“比较已选实验”。这只读取已有证据，不发起新训练。

页面会检查项目、日期、数据和主要费用口径。即使显示基础口径一致，也要核对搜索预算、生成器、奖励、初始池等完整协议；不能只按一个收益数字排序。

### 9.4 当前研究结论

已完成A/B/C/E × 两个种子的8次真实运行，包含48个候选和8次PPO更新。所有最终组合相同，本轮没有显示PPO优势。小预算结果用于验证程序机制，不能据此宣称方法已有效，也不能据此断言PPO永远无效。

## 10. 模型管理与开放选股

### 10.1 查看模型

进入“研究工作区 → 模型管理”，点击“查看 / 管理”。重点查看：

- 模型名称和确切版本编号。
- 计算版本、冻结权重、所需字段、股票范围、当前数据日期。

- 原型数据和已观察历史标识。
- 研究来源；点击“查看来源实验 →”返回具体实验。

### 10.2 修改说明

可修改名称、模型说明、研究者和逗号分隔标签，点击“保存展示信息”。模型说明建议包含使用哪些信号、范围、适用数据、实验结果和限制，不能将得分写成上涨概率。

### 10.3 开放或停用

确认可用性后点击“设为前台可用”。后端会核验当前数据就绪和评价状态；未满足时显示原因，不强行开放。

| 状态维度 | 含义 |
|---|---|
| 候选/可用/停用 | 是否允许用户在前台使用 |
| 评价完成 | 已完成登记要求的评价，不等于收益有效或T必定运行 |
| 当前数据就绪 | 现在能否按该版本要求完成评分 |

模型可以“已设为可用但当前数据未就绪”，也可以“数据就绪但仍是候选”。任一必要条件不满足都会阻止选股。

### 10.4 当前原型一号

模型使用完整500股范围标准化后加权：

```text
综合得分 = 0.4 × 标准化的20日收益率
         + 0.3 × 标准化的负5日收益率
         + 0.3 × 标准化的负20日波动率
```

它偏好中期较强、短期回落、波动相对较低的股票，但多项贡献可能互相抵消。本轮PPO未改善初始组合，名称中的“原型一号”不表示它已被证明能稳定盈利。

## 11. 选股工作台：条件、排名和解释

### 11.1 提交前

选择具体模型版本，展开“模型详情”核对说明与证据；查看实际数据日期。页面日期距当前超过7天会提示过期，但允许明确使用该历史日期计算。刷新页面不会让源文件自动变成实时行情。

切换模型会清空附加条件、使用新模型默认数量并退出原方案上下文，切换后重新检查表单。

### 11.2 设置过滤与数量

数值条件下限和上限都包含边界，留空表示该方向不限；最低值不能大于最高值。不同条件之间为AND，即必须同时满足。

字段值未知的股票不能满足已经启用的相应条件。字段整体不可用时，系统拒绝相关条件，不会静默跳过。

板块字段如果以后核验开放，多选含义是选中板块的并集，再与其他条件取交集；当前没有可用板块选项。

Top N输入正整数。符合条件的股票不足N时，只返回实际数量；系统不会补入不符合条件的股票。没有匹配时显示空结果，这是一次有效计算，不等于程序异常。

### 11.3 评分顺序

1. 在模型固定范围内，按基础资格计算因子及标准化分数。
2. 按冻结权重相加得到综合得分。
3. 应用你的附加条件。
4. 按分数从高到低排名，同分按代码升序。
5. 截取Top N。

因此，修改上市天数条件不会重新训练、不改变权重、不在筛后股票中重新标准化。先取50只再过滤也不是当前规则。

### 11.4 等待与结果计数

点击“生成选股结果”时，系统固定本次提交的模型、数据、条件和N。提交后改表单不会改变正在计算的那一份任务。后台排队时可以继续查看上一次成功结果。

| 计数 | 解释 |
|---|---|
| 模型评分范围 | 模型限定的完整股票数量 |
| 基础资格 | 满足该模型基础资格的数量 |
| 有效评分覆盖 | 合格样本中至少有有效活跃因子观测的数量；不等于所有字段都完整 |
| 用户过滤后 | 同时符合你设置条件的数量 |
| 最终入选 | 截取Top N后的实际数量 |

当前默认无附加条件的成功结果为500 → 500 → 500 → 500 → 50。改变条件后数字会相应变化，不应固定照抄这个示例。

### 11.5 股票解释

点击股票名称或“查看解释”，查看公式、权重、原始值、标准化值、贡献和缺失标记。综合得分是贡献之和。

- 原始值：公式直接算出的特征值。
- 标准化值：相对于当天模型范围内合格样本的相对位置。
- 贡献：标准化值乘冻结权重。
- 缺失：按协议标记，缺失贡献置零；所有活跃因子都缺失或覆盖/退化要求不满足时会阻止相关计算。

分数1.8不是180%收益，也不是80%上涨概率。不同模型或不同日期的分数也不能未经校准直接当成同一概率尺度比较。

自定义条件或改Top N后的配置没有自动生成历史回测，不能直接继承模型原Top K协议的收益曲线。

## 12. 保存方案与修订

### 12.1 从当前表单保存

1. 选定模型、条件和Top N。
2. 点击“保存为方案”。
3. 输入有辨识度的名称，例如“原型一号·上市满一年·前20”。
4. 核对“将保存的固定配置”。
5. 点击“保存方案”。

可以先保存后计算。保存成功不表示已经得到名单。

### 12.2 从某次结果保存

在结果卡片点击“保存本次配置”。它取的是那次结果的模型、条件和N，适合保留历史结果对应的设置；不会误用当前表单后来改过的数值。

### 12.3 加载和重新计算

1. 进入“我的方案”。
2. 查看绑定版本、数量、当前状态。
3. 点击“加载到工作台”。
4. 核对模型、条件和实际日期。
5. 点击“生成选股结果”。

方案绑定具体模型版本，不锁死股票名单，也不锁死旧快照。重新运行要用当时兼容的数据，结果可能变化；若仍是同一数据与同一配置，排名应保持一致。

### 12.4 创建修订

加载方案后修改条件或数量，点击“保存新修订”。系统创建新的方案ID和修订号，旧修订保留。

如果旧条件现在禁用，先查看原因，再显式“清空附加条件”并重新填写可用条件；确认后保存新修订。系统不会自动忽略旧条件替你计算。

模型停用时可查看原方案和历史，但不能悄悄替换版本继续运行。若要使用新模型，应明确选择并保存相应配置。

## 13. 选股记录与导出

## 14. 任务状态、设置和帮助

### 14.1 任务状态

展开“查看任务”可见任务编号、类型、状态、时间及进度；失败时点击“查看错误”。任务包括数据导入、研究、最终测试、对照和选股。

当前本地计算串行排队。长研究占用队列时，后面的选股也可能排队，不代表选股算法卡死。页面可见时约每3秒同步相关运行状态；切到后台标签页可能暂缓页面轮询，后台服务仍可继续计算。

同一任务不要因为页面暂时没变就反复提交。浏览器刷新后可以到任务状态确认，再到实验或历史结果查看。关闭页面本身不会取消后台任务。

### 14.2 设置

默认工作区可选研究或选股；默认每页记录数为20、50或100，影响历史结果分页。点击“保存设置”生效。

当前浏览器会记住最近工作区和未提交的选股草稿，因此默认工作区不一定覆盖已有浏览器记忆。服务端方案/结果与浏览器草稿不是同一对象。

### 14.3 方法帮助

用于快速查阅F/E/V/T、模型交接、过滤顺序、任务控制和评分解释。本文提供更完整的操作步骤；字段是否可用仍以当前数据中心为准。

## 15. 完整操作示例

### 示例A：只使用现有模型

选股工作区 → 选股工作台 → 选原型一号 → 核对日期 → 上市天数最低365 → Top N设20 → 生成 → 看数量和股票解释 → 保存本次配置 → 命名“上市满一年前20” → 导出名单。

下次进入“我的方案”加载，不必重新填条件。要看原来那次名单，进入“选股记录”，不要重新计算后把新名单当旧名单。

### 示例B：运行自己的第一轮研究

1. 数据中心确认500股快照和质量限制。
2. 新建项目“价量研究练习”，记录研究问题。
3. 新建实验“交易增量·种子7·小预算”，保持当前模板。
4. 实验配置检查F/E/V/T、Top K、费用、2批×4候选、Q=6、选择检查点 `[1, 2]`。
5. 运行与迭代 → 启动实验。
6. 查看候选、奖励、PPO更新和批次提交，等待自动V选择。
7. 验证报告 → 按预定计划执行冻结模型T测试。
8. 模型管理 → 查看来源、评价和数据要求 → 填名称与真实描述 → 设为前台可用。
9. 选股工作台 → 选择新版本 → 生成默认名单 → 查看与保存结果。

实验效果不好也保留记录。不要把失败实验删掉，再只展示偶然较好的结果。

### 示例C：中途暂停，第二天继续

运行与迭代 → 检查点暂停 → 等已暂停 → 关闭服务 → 第二天从同一项目目录启动服务 → 打开原实验 → 恢复。

这期间不修改协议、数据快照或代码计算身份。若需要改变设置，则派生新实验，不能借恢复来变更已登记实验。

## 16. 常见问题和故障处理

| 现象 | 常见原因 | 操作 |
|---|---|---|
| 网址打不开 | 服务没运行、端口不同、进程退出 | 按第3章启动，核对终端中的地址 |
| 提示目录锁定或端口占用 | 同目录服务已运行或端口被占 | 先使用已有入口；确认旧服务退出再重启，不删除锁来强开 |
| 无可用模型 | 仍为候选、已停用或列表未刷新 | 模型管理核对状态；刷新页面 |
| 生成按钮不可点 | 未选模型、数据未就绪或已有任务 | 看模型提示和任务状态 |
| 数据日期不是今天 | 原始文件没有新行情 | 核对源文件、导入更新；刷新不会自动下载行情 |
| 换手率/金额输入灰色 | 当前字段核验失败或单位不明 | 查看禁用原因，使用可用条件 |
| 旧方案提示条件不可用 | 旧过滤字段后来被禁用 | 显式调整条件并保存新修订 |
| 没有股票或少于N | 条件太严、资格或覆盖不足 | 看分阶段计数；如要改变条件，显式修改后重算 |
| 得分为负 | 这是相对标准化分数 | 按排名和贡献理解，不当成负收益预测 |
| 名单与回测持仓不同 | 数据日、Top N、条件或成交约束不同 | 对齐模型、日期和协议，查看逐日目标与实际持仓 |
| 训练完成却没有T曲线 | 单实验T没有自动运行 | 验证报告中启动独立T测试 |
| 候选很多但池没改 | 未超过当前组合或阈值 | 查看增量和提交原因，不能以候选数证明改善 |
| 暂停点了仍计算 | 等完整批次或准备阶段结束 | 查看真实进度，等待安全检查点 |
| 服务重启后任务中断 | 队列没有自动续跑 | 普通研究显式恢复，选股重新提交；其他任务查看限制 |
| `model version must be available` | 提交时版本已停用或仍候选 | 刷新模型状态；经决定重新开放或明确选择其他版本 |
| `model scorer identity changed` | 当前评分代码与冻结版本不一致 | 使用匹配代码归档恢复环境，或新建研究版本；不改哈希绕过 |
| `data unavailable` / 必需字段缺失 | 快照范围、历史或字段不兼容 | 看模型数据要求和数据中心，修复输入 |
| 协议JSON无效 | 格式、日期、参数类型或检查点不合法 | 用双引号、不写注释，检查整数/费率及选择批次 |
| 文件不存在 | 登记源路径或代码名单未就位 | 核对第5章路径；换路径时用命令行参数 |
| 数据完整性校验失败 | 冻结文件被改动或拷贝不完整 | 从完整备份恢复或重新导入新快照，不手改摘要 |
| 选股失败但旧名单还在 | 系统保留了上次成功结果 | 查看结果ID和保存时间；旧名单不是新任务成功 |
| CSV代码前导零消失 | 表格软件自动转数字 | 以文本列导入code，原CSV保留代码字符串 |

排查时记录：页面、操作、任务ID、实验/模型/结果ID、完整错误、实际数据日。先保留证据再处理，不要直接删除整个workspace。

### 当前尚不支持的操作

实时行情/API自动同步、定时自动训练/发布、企业多用户权限、自动下单、多模型融合、自然语言过滤、复杂嵌套条件、自定义选股方案历史回测，以及在页面里管理任意全市场上传文件，都不是当前版本能力。界面功能存在不等于历史金融口径已全部验证。

## 17. 备份、恢复及技术附录

### 17.1 保存在哪里

```text
F:\my_code_file\因子构建\生成因子＋回测系统\closed_loop_research\workspace\system_v1\
```

| projects | 项目名称与研究问题 |

旧研究实验和旧系统不在这里统一重写。`workspace/v1_ui_acceptance` 是独立验收目录，不是正式业务数据目录；不用启动它来日常使用系统。

### 17.2 备份

1. 普通研究先暂停到检查点，其他任务等完成。
2. 正常退出服务，确认没有后台写入。
3. 将整个 `workspace/system_v1` 复制到一个新的备份目录，保留目录层级。
4. 同时备份对应版本的 `closed_loop_research` 代码、依赖文件和设计/验收文档。
5. 需要重新导入能力时，另外保留原始TSV和500股代码名单来源。

只备份CSV不能恢复模型、训练检查点或全部历史。实验记录可能包含原工作区的绝对路径，迁移电脑时优先保持原目录布局；改变路径需核对引用和代码身份，当前没有一键跨电脑迁移功能。

恢复时先退出服务，保留当前目录副本，再还原匹配代码和完整持久目录。启动后核对数据、模型、方案和历史，研究任务需显式恢复。不建议在服务运行中覆盖数据目录。

### 17.3 常用命令

### 17.4 完整协议中的高级参数

| 类别 | 主要键与当前默认值 | 用途 |
|---|---|---|
| 表达式空间 | `fields` 24字段；`windows` [1,5,10,20,60]；`constants` [-1,0,1] | 允许生成哪些公式 |
| 容量 | `max_tokens` 15；`max_factors` 5 | 公式长度和活跃组合容量 |
| 预热 | `max_lookback` 120；`field_lookbacks` | 限制总历史依赖，避免窗口缺失或越界 |
| 初始池 | `initial_expressions`；`initial_weights` [0.4,0.3,0.3] | 初始公式与权重，顺序对应，绝对值和为1 |
| 质量 | `min_daily_coverage` 0.95；`max_low_coverage_fraction` 0.05；`max_degenerate_fraction` 0.2 | 覆盖率和退化容忍度 |
| 数值 | `epsilon` 1e-8 | 数值稳定阈值 |
| 搜索 | `search_mode` adaptive；`perturbations` [1,0.5,0.1]；`restart_after` 2 | 内层提案与重启 |
| 选择/时间预算 | `selection_batches` [1,2]；`wall_seconds` null | V候选检查点、可选时间限制 |
| IC | `ic_horizon` 1 | IC评价的未来标签跨度，受分区隔离约束 |
| PPO | `ppo_epochs` 4；`learning_rate` 0.001；`clip_ratio` 0.2 | 策略更新参数 |
| PPO损失 | `value_coefficient` 0.5；`entropy_coefficient` 0.01 | 价值项与熵项权重 |
| 算子 | `operator_profile` extended；`require_feature` true | 算子空间，公式需包含数据特征 |
| 记录 | `compress_artifacts` true | 压缩回测产物，不删除证据 |
| 数据声明 | `synthetic` false；`data_mode` legacy_prototype；`holdout_status` previously_observed_historical | 必须符合实际来源，不能改标签冒充已核验历史 |
| 假设 | `universe_note`；`execution_note` | 记录样本范围、复权、公司行动和成交限制 |

改参数必须新建实验，并保留完整协议。提高预算或放宽质量条件并不自动提高研究可信度；模型是否改善要看预登记、可比较的结果。
