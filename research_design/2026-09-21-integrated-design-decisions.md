# 研究与选股系统：逐项确认记录

状态：功能、首版范围及选股工作台视觉方向已逐项确认。统一设计入口为 `2026-09-21-system-design-v1.md`。本文件保留确认过程与详细规则；实现计划与数值实验配置尚未编写，不代表开始实现。

## 1. 已确认：通用模型＋前台过滤

用户于 2026-09-21 明确选择「通用模型加前台过滤」。首版不建设按用户行业/市值条件分别训练专用模型的流程。

已有确认：新建独立研究系统，选择性复用经过验证的旧组件；原始文件有 441 列，无须全部用于训练，训练字段与前台过滤字段分别选取，可重叠。原始数据事实和时点问题见 `2026-09-21-raw-data-inventory.md`。

### 由此确定的研究边界

- 通用模型在实验指定的较广股票范围内研究，范围仍受数据质量、证券资格和可用历史限制，不能直接等同于无条件覆盖所有 A 股。
- 每个实验固定评分/标准化范围、基本资格规则、Top K 交易协议、字段白名单和时间划分；用户临时过滤条件不进入该实验的组合优化目标或 PPO 奖励。
- 继续采用 v0.4 的组合优化与生成反馈闭环；按行业/市值条件训练专用模型不进入首版。

### 由此确定的计算顺序

1. 加载明确的模型版本及其数据要求。
2. 在该模型规定的当日评分范围内计算因子、预处理与综合得分。
3. 在满足模型基本资格的股票中应用用户基础过滤。
4. 从过滤后的完整候选范围内按分数取 Top N，不是先取模型 Top K 再筛选。
5. 保存实际数据日期、模型版本、过滤配置、N、名单与解释。

前台过滤不重新训练、不改因子权重、不在筛选后的小集合重新标准化。只看某行业的表格视图过滤与生成新名单的候选过滤分开命名。不符合模型数据要求时不能静默删因子再计算。

### 统一对象名称

| 对象 | 内容 | 变化规则 |
|---|---|---|
| 研究实验 | 数据、字段、协议、算法配置与搜索轨迹 | 协议改变派生新实验 |
| 模型及模型版本 | 名称、说明、标签；版本绑定公式、权重、计算规则、适用范围与来源证据 | 因子、权重或计算规则改变产生新版本 |
| 选股方案 | 一个明确模型版本＋基础过滤条件＋Top N | 用户可保存多套；配置变化保存新修订 |
| 选股结果 | 某次实际计算的排名、名单、贡献和输入快照 | 不覆盖历史结果 |

这套名称替代 v0.3 中把模型包直接称为「选股方案」的用法。首版保存方案锁定具体模型版本，不在模型更新时静默切换；换版规则后续在模型管理设计中细化。

### 验证与能力边界

用户可以在有数据支持的条件范围内生成自定义过滤名单；不因没有对应回测就把所有临时过滤一律禁用。页面应区分模型原始验证与该过滤配置是否做过历史评价。此规则替代 v0.3「仅开放预先验证过的配置」的建议。

筛选后的历史评价需绑定模型版本、过滤规则、Top N、执行规则、数据版本与区间，不能拿原模型收益曲线冒充自定义方案收益。是否首版提供用户触发的方案回测，仍待页面与范围阶段确认。所有历史评价沿用信息时点约束；参数选择若使用某区间，该区间不再作为独立测试。

候选不足 N 时显示实际数量，不自动放宽过滤。缺少筛选字段或单位/时点不明确时禁用相应条件并说明原因，不把未知值当作满足条件。

## 2. 已确认：研究自动运行，人工决定模型是否供前台使用

建议以 v0.4 为基础，把研究运行组织为：固定实验协议 → PPO 候选生成 → 组合优化 → 固定 Top K 回测 → 增量奖励 → 更新 PPO 与因子池 → 预定模型选择 → 冻结模型版本。该流程详细设计已存在，但尚未将本次整合后的产品方案视为全部确认。

研究应产出可执行模型包和对应证据，而不只是因子目录/收益图。用户接受以下建议：研究自动迭代，候选模型自动保存，由研究维护者查看验证结果、补充名称说明和标签，选择可供前台使用的模型。

自动保存覆盖实验内部候选与检查点，但不把每个因子、每个临时权重组合都作为前台模型。可供选择的候选模型必须有冻结的执行参数、明确来源和对应评价记录；学习过程中的池变更无需逐次人工批准。人工选择供前台使用与预定研究模型选择协议是两个操作，不能因为人工挑选而把已被查看/选择的数据重新称为独立测试。

该确认不表示所有公式参数、页面细节和实现计划已批准。

## 3. 已确认：模型管理内容与状态

用户已确认本节模型管理方案。模型候选、可用与停用的管理，以及名称说明、标签、版本、来源和验证摘要按下述规则设计。

模型用于呈现一项持续维护的研究成果，具体计算绑定不可变的模型版本。同一模型可以维护后续版本，不同研究配置也可以形成不同模型；不把不同随机种子的临时结果自动命名为不同投资风格。

模型记录分为以下信息：

| 信息 | 内容与来源 |
|---|---|
| 展示信息 | 名称、简要说明、研究者、人工分类标签，可编辑并记录修改 |
| 计算版本 | 因子、权重、预处理、数据要求、评分范围及默认 Top K；改变计算语义必须产生新版本 |
| 研究来源 | 实验 ID、数据快照、字段组、训练区间、检查点、协议与实现版本，自动关联 |
| 评价证据 | 回测/模型选择/最终测试分别标明区间和用途，附成本口径、基线及指标；未运行的项目显示未运行 |
| 使用状态 | 是否已开放前台，以及当前数据是否满足运行要求，分开存储 |

标签分为来源/方法标签与表现标签。价量、财务、PPO 等可由配置形成；低换手、低回撤等描述必须关联实际评价区间和定义，不由名称自动推断。首版不提供自动生成的上涨概率或综合五星评级。

版本的使用生命周期建议：候选 → 可用 → 停用。验证结果/是否完成、数据就绪/异常是独立状态；停用不删除档案，也不影响查看历史名单。验证失败的候选可保留研究记录，但不能伪装成已通过验证的可用版本。具体评价标准由研究协议定义，不临时发明统一收益阈值。

研究端操作：查看候选详情、对比可比结果、填写名称说明、设为前台可用、停用。前台仅列可用模型；已开放但缺少当前数据时展示原因并阻止新计算。首版每个模型指定一个前台默认版本，历史方案锁定具体版本；新版本不会静默替换已保存方案。

模型比较必须显示区间、股票范围、交易与成本配置是否一致。不同口径结果可以并排查看，但不直接做收益冠军榜。前台展示模型摘要，完整搜索记录留在研究工作区。

人工开放前台前应确认模型包可执行、来源与评价记录齐全、字段要求明确；这一步是研究成果管理，不需要审批每轮训练，也不是改变强化学习奖励的途径。

## 4. 已确认：选股工作台流程

用户已确认本节交互流程。该确认不代表已有界面或开始实现；后续第 6 节已确定自定义方案历史评价延后。

### 4.1 打开与选择模型

工作台打开时展示最近一次结果及其实际数据日期，并保留当前编辑配置；没有记录时显示模型选择与明确的空状态。用户一次选择一个可用模型，也可以加载已保存方案。首版不在同一次选股中混合多个模型或平均其分数。

模型选择后就近展示简要说明、标签、具体版本、适用股票范围、数据要求和最新可计算日期。完整验证信息通过详情入口展开；当前数据不满足要求时说明缺失项并阻止新计算。默认按最新完整可用交易日计算，不能把旧数据称为今日结果。历史结果查询在记录页完成，任意历史重算留待研究/评估功能，不混入默认日常流程。

### 4.2 基础过滤与数量

过滤分为证券范围（板块/上市时间等）、规模与活跃度（市值/成交额等）、财务条件（经过核验的盈利与财务指标）三类，具体可选项由已经接入的字段目录决定。市值、行业等未接入时不可假装可选。只有预先配置的筛选字段进入表单，不把 441 个原始字段全部交给用户。

首版条件之间采用 AND；同一分类字段选择多个值时采用集合包含（任一所选值满足即可）。数值条件明确单位、上下限和日期口径。未设置条件表示不增加限制；缺失值不算满足已启用的条件。允许清空附加条件，但不能清除模型规定的基本资格规则或降低计算质量要求。

候选数量 Top N 默认使用模型的研究 Top K 配置，用户可修改；过滤或 N 与验证配置不一致时显示「自定义方案，尚无对应评价」或已有精确配置评价的关联，不继承原配置收益。预估候选数量只统计属性过滤的可用结果，完整计算后的实际数量为准。

### 4.3 生成与结果

主操作是「生成选股结果」。提交时固定模型版本、数据快照、条件与 N，并在后台运行；结果页展示该次提交的实际配置，不能随着表单继续编辑而改变含义。已有结果保留查看，运行或失败状态局部展示；失败不覆盖上一份有效结果。

结果概览显示数据日期、模型版本、入选数、符合条件数和筛选摘要。主表包含排名、代码/名称、综合得分、可用的板块/行业及筛选相关属性。点击股票打开评分解释：因子贡献、关键属性和入选依据；不显示未经校准的上涨概率。未入选与数据缺失原因按需查看。

计数分别说明模型评分范围、基础资格/覆盖情况、用户过滤后数量与最终 Top N，避免把过滤淘汰都称为模型看空。候选不足 N 时只输出实际数量；零结果显示条件与原因，不自动放宽限制。

研究验证摘要与本次选股结果分开展示；生成一次名单不等于已回测这套自定义条件。首版核心流程不要求用户先回测才能生成名单；自定义方案历史评价作为后续范围确认项，不在这里默认扩展实现。

### 4.4 保存、历史与导出

「保存为方案」保存名称、明确模型版本、过滤条件及 N；并不保存一个永远不变的股票集合。可在计算前保存配置，也可在计算后保存，保存配置不表示已经验证效果。下次加载方案用新的可用日期数据生成新名单；条件变更保存新修订。

每次成功计算自动保存不可覆盖的结果记录，无需再点保存结果。保存方案与保存结果是两个对象。前台同时提供结果导出；导出文件包含代码、分数/排名、数据日期和模型版本，另附条件摘要。仅导出当前表格筛选子集时显式标注，不改原始名单。

模型停用或当前缺少必要数据时，已保存方案仍可查看，但不能静默切换版本后继续运行；显示原因，由用户明确选择新版本/模型形成新配置。

### 4.5 概念布局

页面按模型选择与摘要、过滤配置、结果表格、股票详情四个功能区组织，保存方案和导出紧邻其作用对象。不把选择模型、设置过滤、运行计算拆成彼此无上下文的全局菜单。具体布局、组件与视觉样式在第 5 步单独确认。

## 5. 已确认：整个平台的页面结构

用户已确认两个工作区、各三个主要入口的页面结构。后续第 8 节已选定选股工作台视觉基准，其余页面按相同视觉语言细化。

一个系统内分为「研究工作区」与「选股工作区」，通过页头工作区切换进入；各自只有三个主要导航入口。两区共用数据与模型资产，不建设两套评分实现，不要求用户搬文件完成交接。当前项目以研究为建设重点，研究人员首次默认进入研究项目；切换后可记住上次位置。

### 5.1 研究工作区

| 一级页面 | 内容与操作 |
|---|---|
| 研究项目 | 项目及实验列表，创建/打开实验；在同项目下选择同口径实验作比较 |
| 模型管理 | 候选、可用、停用模型及版本；查看证据、编辑说明标签、开放/停用 |
| 数据中心 | 数据源、导入/更新、字段目录与用途、时点和质量检查、快照 |

进入实验后，局部页签为「实验配置」「运行与迭代」「因子与组合」「回测与选股」「验证报告」。这些页签共用实验 ID、协议、数据和模型版本。运行页有启动、检查点暂停、恢复及停止；其他页随真实任务状态展示，不需要用户逐步手工串起算法。

回测与选股页展示研究区间内的排名、Top K 名单、实际模拟持仓及曲线，区间权限受协议控制。这里用于检查模型机制，不是另做一套业务选股引擎。模型保存入口从冻结结果进入模型管理；保留来源跳转。

### 5.2 选股工作区

| 一级页面 | 内容与操作 |
|---|---|
| 选股工作台 | 选择可用模型、附加过滤、Top N、生成名单与查看解释 |
| 我的方案 | 保存配置的列表、加载、另存和修订；显示绑定模型版本及当前可用性 |
| 选股记录 | 日期/方案/模型检索历史结果，查看当时配置、名单与导出 |

选股用户在模型选择位置查看模型摘要与验证详情，不额外增加一套重复的模型管理页面。方案加载返回工作台，历史结果复用相同结果表格与详情组件。

### 5.3 页面内的信息层次

统一使用页头、局部操作栏、主内容、详情面板。研究页面以实验配置和证据为中心；选股页面以名单和筛选为中心。全局仅保留任务状态入口、设置和方法帮助作为辅助功能；任务入口展示状态与错误，不与六个主页面争夺日常导航。

方法公式在实验指标、奖励与验证详情旁按需展开，并提供集中方法说明；不在业务选股首页铺设研究流程图。空数据、未运行、计算中、失败、无符合股票、字段不可用等状态使用与其操作区域对应的提示。

本节确定信息架构与页面职责。具体视觉选择见第 8 节；之前被用户拒绝的早期三张概念图不继续沿用。

## 6. 已确认：首版交付范围和验收

用户已确认本节首版范围、延期功能、建设顺序与验收方向。具体视觉目标和最终数值协议/实施计划仍需落实。

首版目标是让「真实研究闭环 → 可执行模型 → 条件选股 → 保存与追溯」完整运行。页面入口不要求对应复杂独立子系统；每个入口先实现下表中的必要行为。

| 模块 | 首版包含 | 后续扩展 |
|---|---|---|
| 数据 | 已知原始文件的分批导入、字段目录与角色、时点/质量检查、不可变研究快照；模型和过滤只开放核验后的字段 | 数据库/API、多供应商自动同步与定时更新 |
| 研究 | 固定 Top K 协议、PPO 表达式生成、一个可替换的基础组合搜索器、配对交易增量奖励、池版本与检查点、暂停恢复 | 多种高级优化器、代理评价加速、市场状态路由、自动周期重训 |
| 验证 | F/E/V/T 隔离、简单固定因子基线、随机生成对照、单因子 IC 奖励对照、交易增量奖励方法；可配置种子与统一比较口径 | 组合 IC 基线、更多消融与大规模参数研究可在核心对照后逐项扩展 |
| 模型管理 | 冻结包、来源与验证摘要、名称说明标签、候选/可用/停用、版本绑定、人工开放前台 | 自动发布、跨机构模型分发、多用户协作审批 |
| 选股 | 一次选择一个模型，属性过滤，Top N，解释与导出、条件可用性检查、配置绑定 | 多模型融合、自然语言筛选、高级嵌套条件 |
| 方案与历史 | 保存模型版本/条件/数量、修订配置、加载方案、自动保存结果、历史查询与导出 | 通知推送、自动选股调度、批量业务任务 |

首版保留研究回测和模型验证报告；前台自定义过滤条件的独立历史回测暂不列入首版。在结果中明确区分模型已有验证与自定义条件未评价，不编造该方案的历史收益。若用户要求把此功能提前，需补充其历史时点、模型形成时间、缓存和任务预算设计。

当前数据只允许承诺已核验字段的能力。原始财务时点问题优先核对源查询和历史披露版本；能恢复则重建按时点数据，不能恢复则标记不可用于历史训练/过滤。可以用核验后的价量字段先验证计算闭环，但这不等于财务数据修复完成，不能借机宣称财务研究已验收。市值/行业条件需要实际接入支持后才可启用。

### 6.1 建设顺序

1. 数据与交易评价基础：核验字段、信息时点、快照与执行规则，建立可复现评分/净值计算。
2. 独立研究闭环：先验证组合搜索，再接 PPO 奖励与池提交、检查点恢复和测试隔离；通过小预算机制验收。
3. 模型交接：冻结并注册研究产物，确保独立评分接口可加载模型计算新时点数据。
4. 六个主页面：研究项目/模型管理/数据中心及选股工作台/我的方案/选股记录，绑定真实任务与结果。
5. 研究验收：运行预登记的完整对照与多随机种子，检查结果和消融需求。调试预算不作为最终研究证据。

### 6.2 首版验收条件

- 合格数据快照能够驱动一次完整闭环，正负/质量失败候选的处理可追溯；评价实际改变组合搜索，奖励实际进入 PPO 参数更新。
- 每批最多一次池版本提交，下一批加载正确状态；暂停恢复不重复 PPO 更新或遗失提交。
- 最终测试不用于字段/因子选择、奖励、组合搜索或开发停止，相关权限有实际约束。
- 冻结模型独立加载后的评分与研究相同输入一致，无需重启 PPO 或访问可变的实验目录状态。
- 人工开放一个模型后，前台可以选择，按字段条件生成真实排名与名单；过滤顺序、缺失规则和候选不足行为符合已确认设计。
- 方案锁定模型版本，每次结果可追溯到数据日期、快照、条件和 N；新版本及停用不改历史结果。
- 所有展示指标来自实际产物；样本量、训练预算、时间区间及尚不可用字段明确。对照显示负结果也视为有效实验输出，不用收益必须增长作为软件验收。
