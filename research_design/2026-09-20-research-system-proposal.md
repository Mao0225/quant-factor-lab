# 面向固定 Top K 策略的强化学习多因子选股研究系统

版本：0.1，2026-09-20。状态：研究与产品设计草案，未实现新系统，尚未验证研究假设。

## 1. 研究定位

研究问题：在固定的数据、交易规则和计算预算下，使用组合交易表现作为因子生成奖励，能否比使用单因子或组合 IC 奖励，得到更好的样本外多因子选股结果？

核心假设 H1：面向交易结果的组合增量奖励可能改善最终选股表现；H2：这种改善需要考虑因子互补性，而非只挑选单因子指标最高者。假设可能不成立；系统必须同样保存负结果。

不声称发现全局最优股票选择方法，不声称持续迭代必然改善未来收益，不推断结果适用于未公开的企业交易策略。强化学习生成公式、权重搜索、回测执行分别解决不同问题，不把它们包装成一个可直接端到端求导的模型。

旧方案的因子库、静态组合、动态路由是可比较的研究组件，不必全部放入首项实验。首项实验使用固定组合权重；研究迭代更新模型版本，不等于每天实时重训或每天动态切换因子权重。

## 2. 数据定义与信息时点

记 t 为交易日，U_t 为当时可纳入研究的股票集合，X_{≤t} 为截至评分时点已公开且已获得的数据；M 为核验后的可用字段数。用户描述约五千只股票、四百多个原始属性；当前旧缓存的字段数量不是新系统的字段全集，正式实验必须重新核验字段清单。

每个字段登记：名称、含义、单位、类型、来源、事件时间、可用时间、复权口径、缺失比例及可进入表达式的权限。未来收益和任何利用未来数据计算的派生字段只能用于评价，不得进入生成动作空间。只做时间截断并不能修复原始字段已经含有未来信息的问题。

原始层保留供应方记录，标准层统一代码/交易日/数值类型，研究层按不可变的数据快照读取。CSV/Parquet、数据库、行情接口均通过同一适配器契约提供标准数据；模型与界面不依赖本地文件路径。增量更新形成新版本，不静默改变已运行实验。

股票池资格只能使用当时可知信息；不能用全样本流动性选出今天的 500 只股票，再假设它们在过去一直可选。需要记录上市、退市和证券类型变化。若历史成分资料不足，明确限定为固定样本研究并披露样本选择局限。

## 3. 统一数学定义

### 3.1 因子及横截面标准化

第 k 个表达式 f_k 接收截至 t 的历史矩阵，输出股票横截面上的因子值：

\[
a_{k,i,t}=[f_k(X_{\le t})]_i.
\]

该写法允许截面排序等跨股票算子，不把全部因子误写成只依赖单只股票的函数。对当日有有限值的股票集合 V_{k,t} 计算：

\[
\mu_{k,t}=\frac{1}{|V_{k,t}|}\sum_{i\in V_{k,t}}a_{k,i,t},\quad
\sigma_{k,t}^{2}=\frac{1}{|V_{k,t}|}\sum_{i\in V_{k,t}}(a_{k,i,t}-\mu_{k,t})^2,
\]
\[
z_{k,i,t}=\frac{a_{k,i,t}-\mu_{k,t}}{\max(\sigma_{k,t},\epsilon)}.
\]

常数因子截面置零，原始缺失保持缺失标记；第一版默认排除任何非零权重因子缺失的股票，禁止把全缺失股票补零后误选。可用率规则属于锁定的实验协议。标准化股票集合和选股资格过滤的顺序必须固定，训练与应用完全一致。

### 3.2 因子组合与股票目标仓位

\[
s_{i,t}=\sum_{k=1}^{m}w_kz_{k,i,t},\qquad \|w\|_1=1.
\]

w 是因子评分权重，可正可负；L1 归一化固定分数尺度，避免无意义的整体放大。负因子权重不等于做空股票。权重在拟合数据上搜索，评价时冻结。

\[
C_t=\operatorname{TopK}_{i\in E_t}(s_{i,t}),\qquad
u^{*}_{i,t+1}=\frac{b}{K}\mathbf 1(i\in C_t).
\]

E_t 是评分时已知资格与因子覆盖条件下的股票集合，b 是预先固定的目标股票资金比例；不足 K 只时余款留在现金。并列分数按固定证券代码顺序处理。u* 是下一交易日的目标股票仓位，实际仓位由成交引擎决定，不等于因子权重 w。

### 3.3 固定 Top K 执行协议

- 初始研究 K=50、日频评分、下一交易日开盘尝试调仓、等权目标、只做多、不加杠杆。这些是研究设置，不代表最优参数。
- t 日收盘计算信号，只使用当时数据；t+1 开盘执行订单。不能使用 t+1 收盘后才能确定的涨跌停状态提前筛选 t 日名单。
- 未成交买单保留现金，未成交卖单保留原持仓；第一版不自动补入名单之外的股票。锁仓可能使实际持仓数量偏离 K，必须记录。
- 资金约束、可卖数量、交易单位、交易成本、滑点和复权/分红口径全部配置并版本化。成本参数是显式假设，需做敏感性检验。
- 日线不足以识别盘中可成交性时，采用明确的保守近似并记录限制，不把日线回测说成精确成交模拟。

### 3.4 净收益与评价函数

由实际现金和持仓形成日末净值：

\[
V_t=c_t+\sum_i n_{i,t}p_{i,t},\quad
r_t^{net}=V_t/V_{t-1}-1,\quad \ell_t=\log(1+r_t^{net}).
\]

现金 c_t 已扣除实际模拟的手续费与滑点，不在目标函数中重复扣相同费用。n 与 p 须采用一致的公司行动/价格口径。发生破产或无法定义对数收益时，该实验按预设失败规则处理。

建议第一版使用可解释的训练目标：

\[
J_D(B,w)=A\,\overline\ell_D-\frac{\lambda}{2}A\,\operatorname{Var}_D(\ell_t).
\]

B 为因子集合，D 为评价时间段，A 为协议指定的年化交易日数，λ 为预先指定的风险惩罚系数。这是本研究提出的评价选择，不是已证明最优的公式。所有基线使用相同定义；收益、最大回撤、换手和交易成本分别报告，不用一个混合分数掩盖退化。

多段训练内评价可采用：

\[
R(B)=\frac1q\sum_{j=1}^{q}J_{E_j}(B,\widehat w_j(B))
-\eta\operatorname{Std}_{j}\big[J_{E_j}(B,\widehat w_j(B))\big],
\]
\[
\widehat w_j(B)=\operatorname{Search}_{w:\|w\|_1=1}J_{F_j}(B,w),\qquad F_j<E_j.
\]

F_j 是拟合段，E_j 是其后续的训练内评价段；二者均属于开发数据，不能把反复提供奖励的 E_j 宣称为最终样本外测试。权重搜索存在有限预算和局部解，因此写 Search 而不写已经找到全局 argmax。第一版建议有预算上限的多起点扰动/坐标搜索；Top K 的离散排序使直接对真实交易目标做普通梯度下降并不自然。

λ、η、最大因子数、表达式长度与搜索预算在实验协议中明确，当前不填装作已有依据的最优数值。协议未完整前不能启动正式对照实验。

### 3.5 候选因子奖励与 PPO

候选 f 相对当前组合 B 的终止奖励：

\[
r(f\mid B)=R(B\cup\{f\})-R(B)-\beta\Delta C.
\]

C 为预先定义的公式复杂度，例如按最大表达式长度归一化后的 token 数总和；β 为固定复杂度系数，可在消融实验中设为零。候选与基线使用相同的拟合段、评价段、资金规则、成本和权重搜索预算。两边均执行相同预算的拟合，避免只给新组合额外调参机会。该奖励是指定搜索程序下的条件增量，不是严格的因果归因。

PPO 状态为表达式前缀/栈状态与本轮因子池上下文；动作是合法字段、算子、窗口、常数或结束符。合法动作掩码必须参与策略分布计算。语法失败、非有限值、覆盖不足按已登记规则处理；完整合法表达式获得组合增量终止奖励。不能仅因单因子 IC 较低就一律丢弃，它可能对组合有用。

PPO 的 clipped surrogate：

\[
L^{clip}(\theta)=\mathbb E\left[\min\left(
\rho_j(\theta)\widehat A_j,
\operatorname{clip}(\rho_j(\theta),1-\varepsilon,1+\varepsilon)\widehat A_j
\right)\right],\quad
\rho_j=\frac{\pi_\theta(a_j\mid s_j)}{\pi_{old}(a_j\mid s_j)}.
\]

j 是表达式生成步骤，不能与交易日 t 混用；优势估计由终止奖励和价值基线形成。PPO 还需价值损失与熵正则，具体系数版本化。PPO 更新生成分布，不要求穿过排序和回测引擎求导。[PPO 原论文](https://arxiv.org/abs/1707.06347)

因子池变化会改变奖励环境。每个 rollout 批次冻结基线组合、数据窗口、奖励尺度与规则版本，完成该批次 PPO 更新后再更新因子池；其他候选若相对新池重新评估，不能直接复用对旧池的增量。记录奖励归一化原值与训练值。该工程安排降低非平稳混用，不构成收敛保证。

## 4. 研究对照与验证协议

下游组合表现指导因子生成可参考 AlphaGen；原论文的框架与预测评价提供方法基础，本系统把真实交易协议下的净表现引入奖励，是需要重新验证的设计扩展。[AlphaGen](https://arxiv.org/html/2306.12964v1)

主对照至少包括：

| 组别 | 生成/选择方式 | 验证目的 |
|---|---|---|
| 简单基准 | 预先定义的简单评分或多次随机选股，同一执行协议 | 衡量复杂方法是否带来价值 |
| A | 单因子 IC 奖励生成，之后独立组合 | 传统分阶段方法 |
| B | 组合 IC 增量奖励生成 | 因子协同但仍使用预测代理目标 |
| C | 本方案的组合净交易表现增量奖励 | 检验最终目标对齐是否改善结果 |

先固定 B 与 C 的组合搜索程序，仅替换生成奖励以便归因；另设消融比较 IC 拟合权重与交易目标拟合权重。其余消融包括移除增量对照、移除复杂度约束、固定权重/优化权重。不能把同时更换多个组件后的提升全部归因于 PPO。

比较两种预算：相同完整回测评估次数，以及相同墙钟/计算资源预算；明确快速 IC 评价与完整策略回测成本不同。多随机种子报告分布和失败率，不仅挑最佳种子。记录搜索总次数，保留所有被拒绝候选。

按时间顺序隔离开发区、有限次数使用的模型选择区和最终测试区。最终测试在协议与模型冻结后解锁；结果一旦用于修改方案，该区即成为开发数据，需要另找未使用数据。测试隔离由调度器和数据访问边界实现，界面锁图标本身不构成隔离。

因子计算可向前读取已发生的历史作为 warm-up；标签跨边界时删除跨界样本。交易边界的初始资金、已有仓位、建仓成本和样本末平仓处理必须一致。研究收益的置信区间应考虑时间相关性，不把股票×日期的每行都视为独立样本。

重复搜索可能造成回测过拟合；留出数据也会因多次查看而失去独立性。[回测过拟合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

## 5. 一次闭环迭代

1. 锁定研究协议、数据快照、当前基线组合、训练内时间窗口与计算预算。
2. PPO 生成一批合法候选；规范化表达式，缓存因子矩阵，检查覆盖率与禁止字段。
3. 候选组合与基线按相同程序拟合权重；在后续训练内时段执行相同 Top K 回测。
4. 保存净值、订单、成本、权重、奖励各分项及接受/拒绝理由；负反馈也用于学习。
5. 更新 PPO；按预先确定的规则选出可提交的组合变更，不把不同基线上的改善简单相加。
6. 按预算和停止条件迭代；有限次数验证选出冻结模型。最终测试独立运行，研究完成后才用于新数据选股。

快速 IC 只作诊断或明确登记的代理实验，不冒充交易目标。第一版先验证小预算真实闭环，再扩展大规模候选预筛与代理评估器。

## 6. 产品结构：项目—实验—证据

顶层对象为研究项目。项目保存研究问题与数据集；项目内实验绑定一套不可变的研究协议；实验内部有模型版本、候选变更与证据记录。设置、任务队列和日志是上下文能力，不再与研究主流程并列占满导航。

进入实验后的工作阶段：定义协议 → 启动探索 → 检查迭代 → 对照验证 → 冻结模型 → 生成选股快照。允许回看，但修改冻结协议会派生新实验，不能无痕改写旧结果。

主工作区默认回答五个问题：本次在研究什么；固定了哪些条件；当前试了什么变化；为什么接受或拒绝；独立证据是否支持结论。

| 界面区域 | 内容与操作 | 对应研究对象 |
|---|---|---|
| 实验页头 | 研究问题、协议锁、数据日期、运行状态 | protocol / dataset snapshot |
| 主证据区 | 同口径候选与基线曲线、分段结果、不确定性 | R、J 与 paired comparison |
| 迭代记录 | 因子加入/删除、权重变化、奖励、决策理由 | r(f|B)、lineage |
| 上下文解释面板 | 当前公式、符号、计算口径、输入范围、来源文献 | method registry |
| 验证区域 | 时间分区、使用次数、模型冻结状态、最终测试权限 | evaluation protocol |
| 应用结果 | 冻结版本的候选股票、贡献、数据日期和成交前提 | selection snapshot |

公式说明采用“公式—符号—为什么使用—实现口径—局限—证据”模板。点击奖励值可以展开两个对照回测和扣分项；点击因子贡献可以追溯字段与表达式；点击净收益可以追溯订单、费用和日末估值。

界面比较图必须同指标、同单位、同时间/预算轴；不能把 IC 和收益放在不同纵轴上暗示某个方法更优。训练最优值可以用于看搜索进展，但不得替代独立验证曲线。未运行、运行失败、空候选、候选退化等状态均需明确呈现，不能只设计成功页面。

视觉原则：信息密度有层次，少量上下文导航，主图与比较表优先，公式按需展开；不使用装饰性大数字、无定义的综合分、虚构推荐置信度或一屏功能菜单。三张概念图只讨论视觉与交互方向，图片内公式/数值不作为方法定义或实验结果；本文件为方法口径依据。

## 7. 技术边界与验收

建议将研究内核做成独立 Python 包，分别提供数据快照、表达式执行、交易协议、回测、组合搜索、PPO 环境和实验调度接口。正式界面可采用独立 Web 前端，研究计算由后台任务执行；不是在浏览器里训练，也不是每次切换页面重算。

核心持久化对象：DatasetSnapshot、ResearchProtocol、Experiment、CandidateTrial、ModelVersion、EvaluationArtifact、SelectionSnapshot。数据版本、代码版本、随机种子、环境依赖、搜索预算、失败记录必须可追溯。

正式训练前验收：未来信息隔离；复权与现金持仓核算；成交时点；手续费与滑点；失败卖出后的仓位；同分排序；训练/应用评分一致性；恢复后不重复提交候选；两侧比较预算一致。旧回测代码需经过这些检查才能复用，不能因界面可用就视为研究引擎可信。

交付顺序：研究协议与方法说明 → 可核验的小规模闭环 → 同预算对照与消融 → 研究工作台 → 增量数据与冻结模型选股。新系统先独立建立，旧系统作为资产参考保留。

正式实验前待定配置（不阻止概念设计，但必须阻止未定义协议运行）：字段资格、时间分区、交易与成本参数、λ/η/β、表达式空间、因子池上限、计算预算、停止与模型选择规则。未填时显示“协议待完善”，不偷偷采用一套最优值。

## 8. 原理来源与设计选择的区分

- [AlphaGen](https://arxiv.org/abs/2306.12964)：下游组合表现反馈到公式因子生成的研究基础；不等于本方案已被验证。
- [PPO](https://arxiv.org/abs/1707.06347)：策略优化算法来源；组合奖励、数据协议和交易环境是本系统另行定义的内容。
- [Qlib 策略文档](https://github.com/microsoft/qlib/blob/main/docs/component/strategy.rst)：公开 TopkDropout 可作为外部对照；每日完整 Top K 调整与限制替换数量不是同一个策略。
- [The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)：反复策略选择导致过拟合的研究依据。

本草案中净对数收益—方差目标、多窗口稳定性惩罚、有限预算权重搜索和冻结 rollout 因子池属于待验证的设计选择。应通过对照实验支持或否定，不能用公式的存在代替有效性证明。
