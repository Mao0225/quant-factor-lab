# 多因子选股研究系统：按技术方案图收敛的三闭环版本

状态：v0.2 设计草案。依据用户本轮提供的「技术方案」图及反馈；尚未实现新系统。

后续调整：第三节界面与第四节交付范围已由 [v0.3 企业选股产品设计](2026-09-20-enterprise-selection-product-v0.3.md) 替代。企业使用已发布方案日常选股，研究流程进入维护工作区；本稿保留三条研究反馈机制及其验收定义。

本文件补充并调整 v0.1：图用于说明流程和反馈关系，不指定组合优化算法。组合层采用可替换的优化器，具体方法通过同预算实验选择；产品采用可操作的研究系统工作台，不沿用此前三张展示型界面概念稿。v0.1 中数据时点、固定 Top K 执行、收益核算与验证隔离原则继续适用。

## 一、与图对应的系统主线

数据集及字段 → PPO 单因子构建与预处理 → 因子评价 → 候选因子池 → 组合优化 → 横截面评分与 Top K 选股 → 固定交易规则回测 → 评价与反馈。

用户意图落实为可编辑的研究协议：数据范围、字段权限、Top K、调仓和成交规则、风险约束、评价目标、计算预算。它不是未定义的自然语言自动控制器。现阶段以固定 Top K 为交易策略基准。

图中的「因子池＋股票池联合优化」首版明确解释为：在固定的、按时点确定资格的股票范围内优化因子子集与因子权重，再由综合得分决定 Top K 股票。首版不把任意股票代码选择作为另一个优化维度；若后续增加股票池规则优化，必须作为独立变量和对照实验。

## 二、三个闭环，每条反馈必须改变后续执行

### 闭环一：构建质量反馈到因子生成

表达式 → 预处理与评价 → 质量结果 → 生成器反馈 → 后续表达式。

生成期间使用语法动作掩码。完整表达式计算后，检测非有限值、常数退化、覆盖率、字段时点和重复性。无效候选终止本次尝试，并按已登记规则给出质量失败奖励或去重处理；保存拒绝理由。有效候选进入组合评价。

IC、Rank IC、ICIR、Mutual IC 可展示和诊断，不默认把单因子低 IC 作为拒绝门槛，以免提前丢弃互补信号。若使用 IC 预训练，作为单独阶段与对照配置，不把它与最终交易奖励混成不明来源的学习信号。

验收证据：表达式序列、质量指标、失败类型、最终用于 PPO 的奖励，以及更新前后的策略检查点。只记录评价分但不进入学习或明确的筛选更新，不算完成闭环。

### 闭环二：回测表现反馈到组合优化

因子子集和权重 → 股票评分 → Top K 交易回测 → 目标函数评价 → 优化器更新 → 下一轮组合。

每次候选比较固定待优化因子集合。一种可用的组合参数化为：

\[
g=(m_1,\ldots,m_d,v_1,\ldots,v_d),\quad
w_k=\frac{m_kv_k}{\sum_j|m_jv_j|}.
\]

m 是因子是否参与的二元掩码，v 是实数评分系数；全零组合非法，因子数不得超过预设上限。负评分权重不代表股票做空。根据 w 和标准化因子计算股票分数，交给同一个交易执行器。

优化目标采用 v0.1 定义的扣费后净收益—风险目标 J（或另行登记的目标版本），只在拟合段计算。优化器接收目标评价与约束，提出新的因子子集或权重，直到预算耗尽或达到停止条件。记录每次评价、组合变更及对应回测。

优化器契约统一为：输入因子矩阵、交易评价器、约束、初始组合和预算；输出组合参数、评价结果、搜索轨迹及停止原因。增删因子的迭代搜索、无梯度权重搜索或其他方法均可作为候选；遗传算法仅是一个可能实现，不作为需求。具体算法需解释适用条件，并与简单方法做同预算对照。

这是有限预算搜索，不声称全局最优。优化目标不可一会儿使用 IC、一会儿使用收益而不修改协议版本。若采用代理目标拟合权重，必须明确记录，并由真实交易目标评价是否接受该组合。

验收证据：本轮评价结果影响后续搜索状态、提案或组合接受决策；不是重跑相同权重并增加一个迭代计数。只做一次固定权重计算不构成这个闭环。

### 闭环三：组合增量表现反馈到 PPO 因子生成

基线因子池 B → 生成候选 f → 候选和基线分别使用相同优化器及预算 → 后续训练内评价 → 增量奖励 → PPO 更新。

\[
r(f\mid B)=R(B\cup\{f\},\widehat w_{new})-R(B,\widehat w_{base})-\beta\Delta C.
\]

两边权重只在拟合段搜索，R 在后续训练内评价段计算，采用相同交易规则、数据和预算。该段被反复用于奖励，属于开发数据。最终测试完全不进入 PPO 奖励或组合优化目标。

有效但使组合退化的候选也产生可学习的负奖励；不应只收集成功候选。因子池更新后冻结新版本供下一批候选使用；不能把不同基线下的边际改善直接相加。

**一个候选只提交一份明确的终止奖励**：质量失败候选走闭环一的失败奖励；通过质量检查的候选走闭环三的组合增量奖励。避免同一次生成先按 IC 强化、再按交易结果反向强化而不解释训练目标。

验收证据：同一 trial_id 下串起表达式、基线组合、候选组合、两侧回测、奖励分解、PPO 更新和新策略检查点；后续生成实际从新检查点继续。

## 三、系统界面：研究对象组织菜单，运行过程放在工作区

使用普通桌面 Web 管理系统的稳定框架：窄侧栏、页头、内容区、表格、表单、图表、详情抽屉。避免把整张架构图铺满首页，也避免用宣传式大标题取代操作界面。

顶层入口收敛为四个：

1. 研究项目：项目列表、创建项目、打开当前实验。
2. 数据中心：数据源、同步、字段字典、质量报告、按时点股票池。
3. 模型资产：因子与组合版本，查看来源、用于新实验或选股。
4. 实验报告：跨实验比较、对照与消融、报告导出。

任务队列和系统设置放辅助位置。不要再次把 PPO、组合优化器、预处理等内部步骤做成相互断开的全局入口。

进入项目后，核心是「实验工作台」，使用有共同上下文的页签：

| 页签 | 实际操作与内容 |
|---|---|
| 实验配置 | 数据/字段、时间区间、Top K 规则、生成与组合优化方法和预算；常用参数优先，高级参数折叠 |
| 迭代监控 | 启动、请求暂停、检查点恢复、停止；当前轮次、当前候选、组合搜索进度、资源与阶段状态 |
| 因子与组合 | 可排序的因子表、候选评价、当前组合与历史权重、版本差异 |
| 回测与对照 | 净值/回撤/成本、基线和候选对照、训练/验证/测试范围明确标注 |
| 选股结果 | 冻结组合、实际数据日期、Top K 名单、每只股票因子贡献和下载 |

默认进入迭代监控：页头是实验名称、协议摘要和运行按钮；主区上半部是训练内评分轨迹与当前候选，下半部是完整迭代记录表；点击行打开详情抽屉，显示三个闭环的输入、输出和实际变更。日志在底部折叠，不抢占主工作区。

流程进度用紧凑状态条，不用五六个大卡片占满屏幕。按钮须反映真实后台状态；暂停在安全检查点完成，不能只改变前端标签。失败行保留原因、重试范围和已有产物。

每项奖励/指标旁提供「计算说明」，展示公式、符号、区间、成本口径、来源及关联产物。方法说明可以单独阅读，但实验工作台首先要能操作和定位问题。

## 四、最小可交付版本

首版目标是一个能实际走完三个反馈闭环的小规模研究系统，而不是一次实现图中每个可能指标、所有数据供应商或全部优化方法。

- 先支持本地标准化数据源，并预留数据库/API 适配契约；同步能力按实际可用数据源逐项实现，不把未接入接口标为已支持。
- 固定 Top K 交易协议；PPO 生成表达式；可替换的组合优化器调整因子子集和权重；统一回测与训练内反馈。
- 支持有限轮次运行、检查点与恢复、因子/组合版本、迭代证据、独立验证和选股快照。
- 调试小预算只验证程序闭环，正式研究需另设多随机种子、同预算对照、数据隔离与完整搜索记录。
- 画面上的指标全部绑定真实结果；尚未运行显示未运行，接口未接入显示未接入。

## 五、需要证明的不是「越来越好」，而是「反馈确实发生」

闭环验收至少包含一个失败候选、一次由评价驱动的组合搜索更新、一次 PPO 参数更新、一次组合接受或拒绝，以及能够从这些事件追溯到后续执行。训练最优值改善只能说明搜索过程，泛化是否改善仍要由独立验证判断。

当前交付是以上方法和界面结构草案。之前的旧系统与三张概念稿均不作为新系统已完成的证据。
