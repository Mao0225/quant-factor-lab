# 因子研究工作台：模块与交互设计

日期：2026-09-17

状态：模块划分方向已获认可；本文为页面与交互方案，尚未修改应用代码。

## 1. 目标与依据

用户希望按使用场景划分几大块：手动回测独立，PPO 因子生成及其回测集中，减少功能分散，提高用户友好性。同时支持数据与股票池 → 生成 → 回测 → 组合 → 比较的完整研究过程，但不强制按固定顺序操作。

本方案依据 `app/streamlit_app.py`、`custom_bt/results.py`、`custom_bt/platform_jobs.py` 和 AI 研究模块及文档的代码阅读。浏览器预览在默认 Python 环境遇到 NumPy 与绘图依赖冲突，尚未取得有效业务页面截图，因此本文是信息架构与交互设计，不是已经完成的视觉审查。

当前主要问题：

- 11 个平级页签同时容纳业务操作、数据维护、帮助资料、任务和历史结果。
- 左侧常驻 7 个目录配置和 10 个回测参数，参数作用范围不直观。
- PPO 生成与批量回测分开选择生成批次，组合结果还需去另一个页签看详情。
- 生成页和股票池页先展示创建表单，已有记录被放在下方。
- 结果详情先展示大量元数据和备注，再展示曲线。
- `current_job_dir` 被不同操作共享，手动回测区域可能展示其他业务的当前任务。
- 字段和股票列表读取旧缓存，手动回测则优先读取主缓存，缺少统一的数据来源提示。
- AI 任务默认写入 `jobs`，网页默认从 `outputs/jobs` 读取，任务范围不一致。

## 2. 导航结构

采用左侧固定导航，五个业务入口，底部两个辅助入口。各业务模块能独立完成配置、运行、查看结果。

| 入口 | 职责 | 内部页面 |
| --- | --- | --- |
| 手动回测 | 编辑表达式并验证 | 回测工作区、手动回测历史、结果详情 |
| PPO 因子研究 | 生成因子并执行批量回测 | 生成批次列表、新建生成、批次详情 |
| 因子组合 | 使用已有合格因子构建与评估组合 | 组合实验列表、新建组合、实验详情 |
| 数据管理 | 管理研究的数据基础 | 数据概览、股票池、字段与股票、导入更新 |
| 结果中心 | 检索不同来源的历史结果 | 结果列表、结果详情；后续增加跨实验比较 |
| 任务中心（底部） | 汇总各模块后台任务 | 任务列表、任务详情和日志 |
| 系统设置（底部） | 管理目录及默认值 | 存储位置、默认回测参数 |

不增加只展示统计卡片的独立首页。首次打开默认进入手动回测；当前会话内返回工作台时恢复上次所在模块。侧栏显示当前模块以及运行中任务数量。

字段和算子资料保留完整内容：字段归入数据管理；表达式编辑区提供字段与算子帮助面板。算子不再独占一级导航。

## 3. 页面框架

- 顶部：页面标题、当前位置、主要操作。详情页提供明确的返回入口。
- 内容区：只显示当前业务所需信息；常用参数按两列布局，避免长条单列表单。
- 任务反馈：出现在触发任务的模块中，任务中心汇总全部任务。
- 设置：目录集中在系统设置；成本、滑点、手续费等放入当前回测表单的高级参数。
- 数据来源：相关页面始终显示当前缓存名称、股票池名称与规模。完整路径和 ID 放入详情或复制入口。
- 页面宽度不足时表单改为单列，操作按钮与状态文字不得依赖横向滚动才能看到。

## 4. 手动回测

默认进入可直接编辑的工作区，而不是历史表格或数据导入页面。

顺序为：运行名称 → 股票池 → 表达式编辑 → 回测区间与 TopK → 高级参数 → 提交回测。

表达式旁提供“字段与算子”帮助，包含搜索、说明、示例与插入操作；查资料无需离开编辑区。字段必须来自本次回测实际使用的数据缓存。

提交前校验必填项、日期先后、数据可用性和表达式。错误显示在相关输入附近并保留内容。表达式检查复用现有解析能力，不在前端实现另一套语法规则。

提交成功后显示任务状态卡和查看日志入口；任务完成后显示结果摘要与曲线。该模块的任务卡只绑定手动回测提交的任务，不读取其他模块最近一次任务来替代它。

历史记录按名称和日期查找。点击“基于此结果再试一次”恢复该结果的表达式与配置，生成新运行名称，不覆盖原有结果。

## 5. PPO 因子研究

默认展示生成批次列表；“新建生成”打开独立配置区。批次列表显示可读名称、股票池、状态、合格因子数和创建时间。

新建生成配置按四组组织：股票池与字段、训练/验证/测试区间、目标合格因子数、高级生成参数。不同数据区间的含义应有就近说明。

批次详情固定显示名称、股票池和状态，下设三个二级页签：

1. **因子列表**：展示表达式、IC、ICIR、覆盖率等已有指标，以及该批次生成进度。
2. **批量回测**：自动绑定当前生成批次及其股票池；配置回测参数、执行批次内全部合格因子的回测、查看该批次的历史回测及单因子详情。
3. **配置与日志**：查看生成配置、相关任务、失败原因和完整日志。

不再要求在另一一级页面重新选择生成批次。初版沿用现有“回测全部合格因子”能力，不展示尚无执行支持的“仅回测勾选因子”按钮。

无合格因子时说明原因与当前进度；如果批次还在生成，避免将其描述为失败。未满足执行条件时，禁用按钮旁明确说明缺少什么。

批次详情可通过“用于因子组合”带着批次和股票池进入组合配置。第一阶段沿用现有单个来源批次能力。

## 6. 因子组合

默认展示组合实验列表，新建配置分为：

- 来源：股票池、来源生成批次，自动过滤不匹配的批次。
- 因子筛选：排序指标、最低指标要求、相关性阈值。
- 组合设置：规模扫描、最大因子数、已有权重优化配置。
- 回测设置：区间、TopK，以及折叠的资金与交易成本参数。

实验详情直接展示各组合规模的表现表；选择其中一个规模，在本模块内打开指标、曲线和权重明细。无需跳到结果中心才能查看。

显示已有后端返回的候选数、入池数、当前规模和已完成规模。没有可靠总量时显示阶段和数量，不编造完成百分比或剩余时间。

## 7. 数据管理

数据概览优先显示当前可用缓存、覆盖区间、股票数和字段数；存在已有数据时不把导入表单作为默认页面。

股票池页以列表为主，支持查看筛选条件、规模和股票代码。创建股票池表单由明确的“新建股票池”入口打开。

字段与股票页面显式选择或展示数据源，并与研究页面使用相同的缓存解析规则。不能把旧缓存字段标成主缓存的可用字段。

导入更新页包含来源路径、字段、导入选项及任务反馈。对覆盖操作清楚显示目标缓存，保留现有保护，不让用户通过模糊按钮误触覆盖。

## 8. 结果中心与公共详情

各业务模块就地展示自身结果；结果中心用于跨来源检索。两者复用同一结果详情组件和结果数据，不复制结果文件。

列表默认展示名称、来源、股票池、回测区间、TopK、年化收益、Sharpe、最大回撤和创建时间；完整表达式和其他元数据放入详情，避免默认表格过宽。

结果详情顺序统一为：

1. 名称、来源、股票池、区间和配置摘要。
2. 关键表现指标。
3. PNL 与回撤曲线。
4. 年度指标。
5. 表达式；组合结果另外展示成分及权重。
6. 备注与下载。
7. 折叠的完整参数与元数据。

跨实验比较属于第二阶段新增交互：支持多选结果、曲线对比和指标对比。比较前展示股票池、区间、资金和成本设定差异；不同口径的结果不能无提示地排名。第一阶段不放无功能的比较按钮。

## 9. 任务与状态

各模块保留自己的任务关联。任务中心显示类型、名称、状态、进度摘要、更新时间和来源业务入口，支持状态筛选。

状态用文字及图标表达，颜色只作辅助。失败提示先给可理解的原因，再提供展开日志。运行期间避免连续重复提交同一请求；提交状态与计算状态分开表达。

任务刷新应局部进行，保留用户输入、当前选中记录和滚动上下文；保留手动刷新作为补充。后台任务完成后，“查看结果”直接定位到对应业务详情。

网页任务和 AI 任务目录需要统一读取范围或提供明确的来源适配，不能声称已展示所有任务却只扫描其中一个目录。初版可兼容读取两个既有根目录，以完整路径区分记录，不迁移已有任务文件。

AI 研究目前有后端与 CLI，但没有独立网页工作区。本轮不把它包装成可用网页功能；后续可独立增加“AI 研究”，复用上述任务和结果展示。

## 10. 状态与配置边界

- 系统默认值只是新建实验时的初始值；修改默认值不改变历史结果配置。
- 手动、PPO 批量回测和组合拥有各自的编辑草稿，避免共享全局变量导致参数相互影响。
- 跨模块跳转显式携带股票池、生成批次或结果标识；不依赖用户手动重新选择。
- 历史记录使用保存时的配置快照；“再次运行”复制快照到新草稿。
- 切换模块保留会话内未提交草稿。跨应用重启恢复草稿不属于第一阶段范围。

## 11. 实施边界与拆分

先保留 Streamlit 和既有计算引擎，围绕页面、状态和组件拆分现有单文件。建议分为应用入口、页面模块、公共表单/结果/任务组件、数据与状态适配四层。页面只处理展示与输入，既有后端负责生成、回测和组合计算。

第一阶段完成：导航重组、参数归位、PPO 生成与回测合并、模块内结果详情、任务关联隔离、缓存来源一致、历史配置复用。保留当前实际能力和产物格式。

第二阶段再做：跨实验比较、需要后端支持的选中因子回测，以及独立 AI 研究页面。前端框架迁移另行评估，不与本轮导航重组绑定。

## 12. 验收场景

- 从手动回测开始，完成表达式编辑、提交、查看进度和结果，不需要切换一级导航。
- 从 PPO 批次详情发起回测，不需要再次选择该批次和股票池；完成后能在该批次内打开单因子结果。
- 从组合实验列表打开实验，能直接看到规模表现和权重明细。
- 切换模块再返回时，未提交输入和已选记录仍保留；不同模块参数不串用。
- 页面展示字段的数据源与实际回测数据源一致。
- 数据缺失、无生成批次、无合格因子、任务失败等状态都提供明确下一步。
- 手动、PPO 和组合结果详情结构一致，并兼容已有结果。
- 各模块运行中状态不会被其他模块任务覆盖；任务中心能正确标识来源。
- 使用键盘能完成主要操作，焦点可见；状态可通过文字辨认；窄窗口下主要按钮可见。
- 用实际可运行环境完成页面与交互验收。当前预览依赖问题须在此之前解决或切换到已验证环境。
